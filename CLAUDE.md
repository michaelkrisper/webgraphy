# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

WebGraphy — client-only PWA for high-performance data visualization with WebGL. React 19 + TypeScript + Vite. No backend; all data lives in the browser (IndexedDB). Deployed to GitHub Pages from `main`.

## Commands

Package manager is **npm** (ships with Node >=24). CI runs `npm ci`; locally use `npm install`.

- `npm run dev` — Vite dev server. `npm run preview` — serve the production build.
- `npm run build` — `scripts/build.mjs`: `tsc -b` and `vite build` **in parallel** (both tsconfigs are `noEmit`, so they are independent). Either failing fails the build, but a type error no longer stops the bundle, so `dist/` is written even then. `npm run typecheck` runs `tsc -b` alone.
- `npm run lint` — ESLint over the repo. Biome's linter is **off**; Biome only formats.
- `npm run format` / `npm run format:check` — Biome formatter (tabs, 80 cols); CI enforces `format:check`.
- `npm test` — Vitest run (one-shot).
- `npm run e2e` — Playwright smoke + visual regression against the production build (needs `npx playwright install chromium`); `npm run e2e:ui` for the inspector. Screenshot baselines live in `e2e/**-snapshots/` and are generated by CI in the pinned Playwright container, never locally — GPU rasterisation differs per machine.
- `npm run size:check` — production build vs. the gzipped size budget in `size-budget.json` (per entry plus the PWA precache total; what CI runs). `npm run size:update` re-records it; `npm run analyze` writes a per-module composition report to `dist/bundle-report.html`.
- `npm run bench:check` — hot-path benchmarks vs. `bench-baseline.json` (what CI runs; `npm run bench` alone just measures). **Advisory locally, binding in CI** (`CI=1` makes it exit non-zero): a busy developer machine skews the numbers past the tolerance without anything being wrong. The run also self-checks — if throughput drifts >10% between the control measured first and the one measured last, it reports the run inconclusive instead of inventing a regression. Benchmarks live in `src/__bench__/`; regenerate the baseline from an idle machine or from CI's `bench-result` artifact via `node scripts/bench-check.mjs --update`.
- `npx vitest run --coverage` — tests with coverage thresholds enforced (what CI runs). Thresholds live in `vitest.config.ts`; the build fails if coverage drops below them. Ratchet up, never down.
- Single test file: `npx vitest run src/utils/formula/__tests__/parser.test.ts`
- Single test by name: `npx vitest run -t "name substring"`
- Watch: `npx vitest`

`@` is aliased to `./src` (see `vitest.config.ts`). Tests run in jsdom; `src/__tests__/setup.ts` mocks `localStorage`. Vitest runs with `fileParallelism: false` (benchmarks must not compete for CPU) and excludes `e2e/`, whose `*.spec.ts` files are Playwright-only.

CI (`.github/workflows/ci.yml`) is the only workflow: a `quality` job (format → lint → coverage test → build → size budget), a containerised `e2e` job, an advisory-but-binding `bench` job, and a `deploy` job that publishes `dist` to Pages on `main`. (The README still refers to a separate `deploy.yml` on `master` — stale.)

## Architecture

### Data flow
File import → **parser web worker** (`src/workers/parser.worker.ts` → `utils/data-parser.ts`) → `ParsedDataset` with columns as **`Float32Array`** → store `addDataset` resolves the x-axis column + axis slot → IndexedDB. XLSX goes through a separate **excel worker** (`workers/excel.worker.ts`, carries the whole SheetJS bundle — lazily constructed and deliberately excluded from the PWA precache). Calculated columns go through the **formula worker** (`workers/formula.worker.ts` → `utils/formula.ts`). `workers/WorkerClient.ts` is the shared request/response wrapper (id-keyed promises, lazy worker construction); the `*Client.ts` files are its instances. Workers transfer `ArrayBuffer`s (zero-copy); never assume a buffer is still usable after posting.

### State — `src/store/useGraphStore.ts` (Zustand)
Single store holding `datasets`, `series`, `xAxes`, `yAxes`, plus UI flags. Key model facts:
- There are always **9 fixed x-axis and 9 fixed y-axis slots** (`axis-1`..`axis-9`), created up front. Adding data assigns a dataset to a free x-axis slot; it does not create axes.
- A **`SeriesConfig`** binds a dataset column (`sourceId` + `yColumn`) to a `yAxisId`. A **`Dataset`** owns one `xAxisColumn`/`xAxisId`.
- Persistence is **split and debounced**: `debouncedSaveViewport` (axis min/max, 250ms), `debouncedSaveConfig` (series + toggles, 150ms), `debouncedSaveState` (both), plus immediate per-dataset `persistence.saveDataset`. Writes are gated on `isLoaded` and scheduled via `requestIdleCallback`. When adding store actions that mutate data, follow the existing pattern of calling the matching debounced saver.
- On startup `loadPersistedState` restores from IndexedDB, else loads demo data (`services/demoData.ts`).

### Persistence — `src/services/persistence.ts`
IndexedDB (via `idb`), DB `webgraphy-db` v2: a `datasets` store (large typed-array payloads) and an `app_state` store (viewport + config under separate keys). All loaded state is validated with **Zod** schemas before entering the store — keep schemas in sync when changing the `Dataset`/`*Config` interfaces (also exported from this file).

### Rendering — `src/components/Plot/`
The hot path. `ChartContainer.tsx` orchestrates; it does **not** re-render per frame. Everything on screen inside the plot — series, grid, spines, ticks, **and all text** — is WebGL; there is no 2D-canvas axis layer any more.
- `rendererCore.ts` is the framework-free **WebGL2** renderer driving three GLSL ES 3.00 program pairs from `rendererShaders.ts`: `MAIN` (point sprites + screen-space overlay), `LINE` (instanced triangle-capsule series lines), `LABEL` (textured atlas quads). `GLStateCache.ts` caches uniforms/attribs/divisors across programs.
- It runs inside `workers/render.worker.ts` via `OffscreenCanvas` when supported, else on the main thread — `renderBackend.ts` picks the backend (`WorkerBackend`/`DirectBackend`, StrictMode-safe: a canvas can only be transferred once) and `WebGLRenderer.tsx` is the thin React host that resolves store data into plain renderer inputs.
- Series lines are never drawn with native `gl.LINES`/`LINE_STRIP` (driver line width caps at 1px on ANGLE/D3D and core profiles). Each segment is an instanced quad expanded in the vertex shader from `gl_VertexID` + per-instance endpoints read straight from the column buffers (4-byte stride/offset trick), shaded with a capsule SDF for AA, real widths, round joins, and dashes. Only 1px overlay primitives (grid/spines/ticks) still use native LINES.
- Text: `buildLabels.ts` computes the per-frame label list (pure, testable); `labelAtlas.ts` shelf-packs rasterised runs into a shared texture (`OffscreenCanvas` in the worker, DOM canvas on the fallback path) and overflow resets the atlas wholesale.
- Decimation is **M4** (`utils/decimation.ts`): pixel-anchored buckets plus an octave-merge pyramid, cached per series in `decimationCache.ts`.
- **Scene building**: the worker rebuilds the whole scene itself via `frameScene.ts` (ticks, overlay geometry, labels) from a slim `SceneContext` that only changes on config/theme/resize. The host stops computing overlay/labels as soon as it has sent that context (`sceneShared()`); before then, and on the main-thread backend, it computes them itself and calls `setOverlay`/`setLabels`. Keep both alive — the early frames use the host path.
- **Viewport transport**: with `crossOriginIsolated`, `viewportChannel.ts` writes the axis ranges into a `SharedArrayBuffer` behind a seqlock and the worker's rAF loop polls it, so pan/zoom costs zero postMessages. Without it the ranges ride on the `frame` message and the worker derives the scene from those (`fillPostedSnapshot`). `vite.config.ts` sets COOP/COEP on dev and preview only and GitHub Pages cannot set headers, so **production takes the postMessage transport** — which is why `e2e/smoke.spec.ts` runs one test with `crossOriginIsolated` stubbed to false.
- The worker backend mirrors only the columns of live series (keyed by `Float32Array` identity, pruned symmetrically) — never assume the worker has data the last `series` message didn't reference.
- Pan/zoom and keyboard nav mutate **target ref objects** (`targetXAxes`/`targetYs`), and a `requestAnimationFrame` loop interpolates → redraws imperatively, only writing back to the Zustand store when interaction settles (`syncStoreUpdates.ts`). This ref+rAF indirection is deliberate: do not "simplify" it into render-driven state, and avoid adding store subscriptions or React state on the per-frame path.
- Layout math is extracted into pure, individually-tested modules (`computeAxesLayout`, `buildXAxisLayout`, `axisGutters`, `seriesPrep`, `drawSeries`, `buildOverlay`, `overlayGeometry`, etc.). Prefer adding/adjusting these pure functions over inlining logic into components.

### Formula engine — `src/utils/formula.ts`
A re-export facade over `src/utils/formula/`: `parser.ts` (lexer → shunting-yard RPN), `compile.ts`, `evaluate.ts` (row-wise interpreter over a pre-allocated stack), `stateful.ts` (rolling/time/group state), `wholeColumn.ts` (regression/KDE/group-average paths, which can emit a compact sparse sub-dataset). **No `eval`/`new Function`**; column refs and function names are validated against the dataset and `formulaFunctions.ts` (the single source of truth for functions — add new functions there).

## Conventions

- Tests are colocated in `__tests__/` next to the code (also some `*.test.ts` beside source). Pure logic is unit-tested directly; components use Testing Library; accessibility is asserted with `vitest-axe`.
- Numeric column data is `Float32Array`; dates/large numbers use a `refPoint` offset (`isFloat64`) to preserve precision — respect this when reading/writing column data.
- ESLint flat config (`eslint.config.js`) includes `react-hooks` and `react-refresh` rules; the codebase is lint-clean and CI enforces it.
